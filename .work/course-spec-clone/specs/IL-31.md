- title: IL-31 · AI Red-Teaming & Safety Evals Engineering
- tagline: Evaluate, red-team, and harden frontier AI systems — the measurement discipline behind safe AI deployment.
- blurb: The AI industry learned to build agents faster than it learned to measure them. This course is the missing half: how to design evaluations that honestly measure what frontier AI systems can and cannot do, how to red-team them like a professional, and how to report findings responsibly. From METR's RE-Bench and time-horizon methodology to autonomous-agent eval harnesses, cyber capability evals, bias and fairness methodologies, interpretability for evals, and responsible disclosure, every module is built on published sources with an explicit defensive framing — evaluating and defending AI systems, never attacking them.

## Learning Outcomes (objectives)
1. Define AI red-teaming as a defensive engineering practice and map classic threat models (threat actors, attack surfaces, impact paths) onto AI systems.
2. Classify prompt injection and jailbreak techniques by published taxonomy, describe how evaluators detect each class, and name the defenses that counter them.
3. Design a complete eval: task definition, scoring rubric, contamination controls, baselines, statistical power, and a written threat-to-validity section.
4. Distinguish capability evals, safety evals, and alignment evals, and select the right type for a given deployment question.
5. Explain METR's RE-Bench design, the task-time-horizon method (50%/80%), and the published doubling trend — including what the metric does NOT claim.
6. Build sandboxed eval harnesses for autonomous agents: tool-use logging, isolation boundaries, timeout and rollback controls.
7. Describe how cyber capability evals are run defensively (vulnerability discovery benchmarks, vetted-access tiers) per Anthropic's published Cyber Verification Program expansion (Oct 6, 2026).
8. Run bias and fairness evaluations using published methodologies (demographic disaggregation, counterfactual pairs, published benchmark families).
9. Apply interpretability techniques (feature probes, attention/latent tracing, counterfactual activation) as eval evidence rather than model internals trivia.
10. Write a responsible disclosure report for an AI vulnerability: scope, reproduction, severity, remediation advice, and coordinated disclosure timeline.
