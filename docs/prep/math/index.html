1. Arithmetic

You already use this. We name it so later formulas do not feel like magic.

  • Add / subtract — combine or remove quantities (CPU cores, tickets, dollars).
  • Multiply — repeated add (3 replicas × 2 GB = 6 GB).
  • Divide — split into equal parts (1000 req / 4 pods = 250 req each).
  • Order — parentheses first, then ×÷, then +−. Same as most calculators.

Worked · disk

You have 500 GB free. Each log day uses 12 GB.
Days until full ≈ 500 ÷ 12 = 41.666… → about 41 full days.
Alert earlier: at 80% used you have 20% of 500 = 100 GB → 100÷12 ≈ 8 days left.

2. Algebra (letters for unknowns)

A letter stands for a number you do not know yet. Solving means isolating that letter.

If pods × rps_per_pod = total_rps
Then pods = total_rps ÷ rps_per_pod

Example: need 2000 rps, each pod does 250 rps
pods = 2000 ÷ 250 = 8

Balancing: whatever you do to one side, do to the other.

2x + 6 = 20
2x = 20 − 6 = 14
x = 14 ÷ 2 = 7

3. Exponents & logarithms

Exponent: multiply a number by itself. 210 = 1024 (why “kibi” feels like ~1000).

Logarithm: asks “what power?”. log2(1024) = 10. In ops, log scale shows orders of magnitude (latency histograms, storage growth).

Storage doubles every year: year0=100GB, year3=100×2³=800GB
Rough “how many doublings to 1TB from 100GB?”
1TB=1000GB ≈ 100×10 → need factor 10 → a bit more than 3 doublings (8×) so ~3.3 doublings.

4. Probability & stats basics

  • Probability between 0 and 1 (or 0–100%). Independent failures multiply: P(both down)=P₁×P₂.
  • Mean — average. p95 — 95% of samples are at or below this value (latency SLOs).
  • Error budget — if SLO is 99.9% success / month, allowed failure fraction is 0.1%.
30-day month ≈ 30×24×60 = 43,200 minutes
0.1% of 43,200 = 43.2 minutes downtime allowed for a 99.9% monthly availability SLO

5. Binary & hexadecimal

Computers count in powers of 2. Hex groups binary by 4 bits.

Decimal 13 → binary 1101 (8+4+0+1)
Hex digits: 0-9 then A=10 … F=15
0xFF = 255 = 1111 1111
IPv4 address = 4 bytes. 10.0.0.1 in hex often written in configs as paired bytes.

Powers of two to memorize: 2,4,8,16,32,64,128,256,512,1024.

6. Rates, percentages, ratios

Percentage: part/whole × 100
CPU 2.5 cores of 4 → 2.5/4×100 = 62.5%

Rate: quantity per time (req/s, MB/s)
Ratio: compare two quantities (3:1 read:write)

Change %: (new−old)/old × 100
Latency 200ms → 150ms: (150−200)/200×100 = −25% (faster)

7. CIDR & subnet math

IPv4 has 32 bits. A CIDR prefix length /N means N bits identify the network; 32−N bits identify hosts.

Host bits = 32 − prefix
Addresses in block = 2^(host bits)
Usable hosts ≈ addresses − 2 (network & broadcast) on classic subnets

/24 → host bits 8 → 256 addresses → ~254 usable
/16 → host bits 16 → 65,536 addresses
/20 → host bits 12 → 4096 addresses

Example: 10.10.0.0/20
Block size 4096. Next subnet starts at 10.10.16.0
First usable often 10.10.0.1, last 10.10.15.254 (training simplification)

Azure/AWS often reserve more than 2 addresses — always check cloud docs in interviews and say so.

8. Reliability: nines, MTTR, MTBF

Availability ≈ MTBF / (MTBF + MTTR)
MTBF = mean time between failures
MTTR = mean time to repair

"Three nines" 99.9% ≈ 8.76 hours downtime/year
"Four nines" 99.99% ≈ 52.6 minutes/year
"Five nines" 99.999% ≈ 5.26 minutes/year

Interview tip: state assumptions (calendar year, planned vs unplanned).

9. Capacity & cost math

Required instances = ceil(peak_load / capacity_per_instance / target_util)
Peak 1200 rps, each VM 400 rps, target util 70% → effective 280 rps
1200/280 ≈ 4.29 → 5 instances

Monthly cost ≈ instances × hours × $/hour
5 × 730 × $0.12 ≈ $438/month (rough)

Always add headroom for deploys, AZ loss, and retry storms.
