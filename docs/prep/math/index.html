0. Boolean algebra (ops logic)

Alerts, firewalls, and feature flags are Boolean expressions. Build truth tables until AND/OR/NOT are automatic.

AND  — true only if both inputs true
OR   — true if either input true
NOT  — flips true ↔ false

Practice: page on-call IF disk > 90% AND CPU > 80%
 disk>90 | CPU>80 | alert?
   F    |   F    |  F
   F    |   T    |  F
   T    |   F    |  F
   T    |   T    |  T

Variant: page IF disk>90% OR memory>95% — different table.

Interview say: “I translate runbook conditions into Boolean expressions and verify edge cases with a truth table before wiring the monitor.”

1. Arithmetic

You already use this. We name it so later formulas do not feel like magic.

  • Add / subtract — combine or remove quantities (CPU cores, tickets, dollars).
  • Multiply — repeated add (3 replicas × 2 GB = 6 GB).
  • Divide — split into equal parts (1000 req / 4 pods = 250 req each).
  • Order — parentheses first, then ×÷, then +−.

Worked · disk

You have 500 GB free. Each log day uses 12 GB.
Days until full ≈ 500 ÷ 12 = 41.666… → about 41 full days.
Alert earlier: at 80% used you have 20% of 500 = 100 GB → 100÷12 ≈ 8 days left.

2. Algebra (letters for unknowns)

If pods × rps_per_pod = total_rps
Then pods = total_rps ÷ rps_per_pod

Example: need 2000 rps, each pod does 250 rps
pods = 2000 ÷ 250 = 8

3. Exponents & logarithms

Exponent: multiply a number by itself. 210 = 1024.

Logarithm: asks “what power?”. log2(1024) = 10. Ops angle: B-tree / index lookups track like O(log N); full scans like O(N).

1,000,000 rows:
O(N) scan ≈ touch a million rows
O(log₂ N) ≈ log₂(1e6) ≈ 20 comparisons (index intuition)

Storage doubles every year: year0=100GB, year3=100×2³=800GB

4. Probability & stats basics

  • Mean — average for capacity planning.
  • Median — middle value; resists outlier spikes.
  • Percentiles (p95/p99) — latency SLOs and alert thresholds.
  • Probability 0–1; independent failures multiply.
Alerting: page on p95 latency > 300ms for 5m — not on a single noisy mean spike.
30-day month ≈ 43,200 minutes
0.1% of 43,200 = 43.2 minutes downtime for a 99.9% monthly SLO

5. Binary & hexadecimal

Decimal 13 → binary 1101 (8+4+0+1)
0xFF = 255 = 1111 1111
Powers of two: 2,4,8,16,32,64,128,256,512,1024.

6. Rates, percentages, ratios

CPU 2.5 cores of 4 → 2.5/4×100 = 62.5%
Change %: (new−old)/old × 100
Latency 200ms → 150ms = −25%

7. CIDR & subnet math

Host bits = 32 − prefix
Addresses = 2^(host bits)

10.0.0.0/24 → host bits 8 → 256 addresses → ~254 usable (classic)
/16 → 65,536 · /20 → 4,096

Say in interview: “/24 is a Class-C-sized lab subnet; Azure reserves extra addresses — I check docs.”

Practice drawing 10.0.0.0/16 split into /24 app, data, and management subnets.

8. Reliability: nines, MTTR, MTBF

Availability ≈ MTBF / (MTBF + MTTR)
99.9% ≈ 8.76 h/year · 99.99% ≈ 52.6 min/year

9. Capacity & cost math

Required ≈ ceil(peak / (per_instance × target_util))
Peak 1200 rps, VM 400 rps, util 70% → 5 instances
Cost ≈ instances × 730 × $/hour

Phase 1 practice set

  1. Truth table for (disk>90 AND cpu>80) OR load>4.
  2. Given 12 latency samples, compute mean, median, p95 (interpolate OK).
  3. Explain O(log N) vs O(N) for “find user by ID” with and without an index.
  4. How many usable hosts in 10.10.0.0/20? What is the next subnet?
  5. Teach-back (90s): CIDR to a non-engineer PM.
