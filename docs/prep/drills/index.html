Prep · Track D

Interview drills

Practice out loud. Time yourself. Record one answer per day. Framing: versatile engineer focused on operations — never “only an operator.”

Identity framing (use carefully)

I build and run systems as an engineer: code, pipelines, and platforms.
Portfolio labs (Interstitium, DevOps SuperLab) show how I learn in public —
they are inspectable products, not a claim of senior paid tenure.

Explain-back prompts (90 seconds each)

  1. What is CIDR and why does /20 matter for a VNet plan?
  2. Explain Terraform state and why locking matters.
  3. Docker image layers — what invalidates the cache?
  4. How does Vault differ from putting secrets in env files?
  5. What is an SLO vs an alert?
  6. Walk through a blue/green vs rolling deploy tradeoff.
  7. How would you revoke a leaked cloud key in the first 15 minutes?

Whiteboard scenarios

  • Design CI/CD for a Java service to Azure with approvals for prod.
  • Network diagram: users → WAF → app → managed DB; mark trust boundaries.
  • On-call: p99 latency doubled after deploy — what do you check first?
  • Migrate snowflake VMs to Packer images + scale sets — sequence the work.

Method: clarify constraints → sketch → call out risks → propose metrics.

Script katas (pair with Programming)

# 25-minute box
1) Bash healthcheck with retries + timeout
2) Python parse JSON inventory → print prod hosts
3) Jenkinsfile with test gate before docker build

RCA story framework

Context → Detection → Timeline → Impact → Root factors
→ Mitigations → Prevention → What I learned

Keep blameless. Quantify (users, $$, minutes). End with a control you would add.

Behavioral bank

  • Tell me about a time you automated toil.
  • Conflict on a change window — how did you resolve?
  • Learning something hard (Terraform/Vault) — evidence?
  • Mistake in production or lab — what changed after?
