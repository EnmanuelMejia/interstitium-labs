Tailored interview preparation for Enmanuel applying to a bank–style Sr. Associate DevOps Engineer role. This is a study aid — not a claim of a desk employment, affiliation, or offer.

Framing rules

  • Say “lab / portfolio / study project” for Interstitium & SuperLab unless describing paid work.
  • Map IT ops tickets → automation narrative without inflating titles.
  • Prefer Azure depth for this JD; name AWS only as prior exposure if accurate.
  • Every story ends with a control you added (test, alert, IaC, runbook).

Tell me about yourself (60–90s)

Prep only. Honest elevator — IT ops → DevOps bridge. Does not claim “5+ years senior DevOps,” or present Jenkins-for-300-users as paid tenure.

Spoken script · ~75 seconds

“I build Interstitium Labs. The work is the record.”

Honesty guardrails (do not say)

  • Do not say “DevOps Engineer with 5+ years” unless that title and tenure are true on a W-2/offer letter.
  • Do not name a former employer that is not listed on the public bio.
  • 300+ users = VoIP / PC support footprint — not “I ran Jenkins for 300 users” as paid production CI ownership.
  • Jenkins, Terraform, Kubernetes, Prometheus: label as lab / portfolio / study unless you can show paid production ownership.
  • SuperLab / Interstitium = portfolio evidence, not employer of record.

STAR tips for the opener + follow-ups

  • Situation: Scale + constraint (300+ users, VoIP/RHEL, budget, team of 22).
  • Task: Your lane — uptime, policy, supervision, procurement — not “the company’s DevOps transformation.”
  • Action: One concrete control you added (inventory system, DR process, AD hygiene, training).
  • Result: Measurable if true (response times, downtime avoided); otherwise qualitative + what you would automate next.
  • Bridge line: “That ops pressure is why I’m practicing Pipeline-as-Code and IaC in Interstitium / SuperLab — so the next role inherits automation, not heroics.”

Also link: Founders bio · Public resume highlights · Full-stack desk VP path (separate JD — do not mix stories).

STAR method (use on every answer)

Situation — context, blast radius, constraints
Task     — your responsibility (not the team’s)
Action   — what YOU did (tools, decisions, tradeoffs)
Result   — measurable outcome + what you locked in after

Keep answers ~90–150 seconds. Quantify (users, minutes, %, dollars). Blameless RCA language.

Part 1A · Technical & hands-on

CI/CD & Jenkins

  • Walk through a Declarative Jenkins pipeline you built (or labbed): stages, agents, secrets, failure post.
  • How do you keep Pipeline as Code reviewable? Credentials IDs vs hardcoded secrets?
  • Where would SAST/DAST (e.g. Snyk / Trivy) gate the pipeline without blocking every WIP branch?

STAR tip: Situation = flaky manual deploy; Action = Jenkinsfile + artifact versioning; Result = fewer rollback windows + audit trail.

IaC · Terraform & Ansible

  • Describe a Terraform project: remote state, locking, plan-before-apply, module boundaries.
  • Ansible vs Terraform — when each? (desired state config vs cloud resource graph).
  • How do you stop secrets from landing in state or playbooks?

STAR tip: Emphasize plan as contract and least-privilege SPN/managed identity.

Azure & Linux

  • Hands-on Azure: VNet/NSG, VM or App Service, RBAC, Monitor — be specific about what you personally provisioned (portal → then Terraform).
  • Cost optimization story: rightsizing, reserved/spot, idle teardown in labs.
  • Linux tune: top/htop, journalctl, ss, disk I/O, sysctl awareness — outcome?

Docker & Kubernetes

  • Image hygiene: non-root, multi-stage, layer cache, scan.
  • K8s exposure (course/lab/managed): Deployments, Services, probes, namespaces — clarify managed vs self-managed.
  • Networking between containers: bridge vs overlay vs service DNS (high level is fine).

Python / Bash / Groovy

  • Pick one script that cut toil (~20% style claim only if true): inputs, failure modes, how scheduled.
  • Decision tree: Bash for glue/pipes; Python for APIs/JSON/logic; Groovy only inside Jenkinsfiles.

Prometheus / Grafana

  • What scrapes what? Golden signals / USE-RED. Alert on symptoms users feel.
  • Metric-driven automation example: threshold → runbook or scale action (even if labbed).

Part 1B · Behavioral & methodology

Agile collaboration

  • Role in standups/planning/retros with developers & QE.
  • Disagreement on deploy approach — how you resolved with data + risk.

RCA / incidents

  • Most complex incident (prod or serious lab): timeline → impact → factors → prevention.
  • Structure an RCA: blameless, contributing factors, corrective + detective controls.

Mindset

  • “Software engineer focused on operations” — you write tests, automate, treat infra as code; you are not ticket-only.
  • How you stay current: Microsoft Learn, HashiCorp Learn, leading lab platforms, public labs on GitHub.

Part 2 · desk remote interview process

  1. Recruiter screen (~30 min) — story fit, logistics, compensation band awareness.
  2. Technical (HM + seniors) — Microsoft Teams primary; expect screen share of terminal, Jenkinsfile, or Terraform.
  3. Possible coding / IaC — CoderPad, Teams whiteboard, or short take-home.
  4. Cultural fit — senior director; risk, collaboration, learning velocity.

Day-of checklist

  • Install & test Microsoft Teams (camera, mute, screenshare a terminal window).
  • Quiet, lit space; water; resume + JD printed or second screen.
  • Honest 60–90s “Tell me about yourself” rehearsed once (see above) + 3–5 STAR stories (VoIP/AD ops, supervision, incident/RCA, lab Jenkins/Terraform, collaboration).
  • Repo links ready (portfolio READMEs) — open before the call.

Questions to ask them (pick 3–5)

  1. How is Pipeline as Code owned — platform team vs product squads?
  2. What’s the golden path for Azure + Terraform state in this org?
  3. How do you balance change control with deploy frequency?
  4. What does on-call look like for this team in the first 90 days?
  5. Which skills separate a good Sr. Associate from a great one here?
