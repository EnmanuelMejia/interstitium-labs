Prep · Track C

DevOps ↔ JD map

Each module maps to bullets typical of a Sr. Associate DevOps Engineer JD in fintech (BNY Mellon–style). Prep only — not an employment claim. Pair with Math and Programming.

How to study each module

  1. Read the “say in interview” line aloud.
  2. Do the lab minimum.
  3. Write a 5-bullet RCA or design note in your evidence folder.

1. Git & collaboration

JD: branching, PRs, code review culture.

git switch -c feat/healthcheck
git add . && git commit -m "add healthcheck script"
git push -u origin HEAD
# open PR; request review; squash merge

Say: “I treat infra as code in Git — small PRs, protected main, signed-off reviews.”

2. Linux administration

JD: processes, users, permissions, journals, packages.

systemctl status nginx
journalctl -u nginx -n 100 --no-pager
ss -tulpn | head
chmod 640 /etc/app/app.env   # know octal from Math track
useradd -r -s /usr/sbin/nologin appuser

3. Networking & firewalls

TCP vs UDP, DNS, TLS termination, security groups / NSGs, least privilege.

# Conceptual: allow 443 from internet → load balancer
# allow 8080 only from LB subnet → app subnet
# deny all else
curl -v https://example.com  # read TLS handshake errors

4. Public cloud (Azure-first, cloud-fluent)

Subscriptions, resource groups, IAM/RBAC, VNets, managed identities, cost tags. Also know AWS/GCP equivalents by name.

Lab min: deploy a VM or App Service + NSG + diagnostic settings via portal once, then recreate intent in Terraform.

5. Ansible

- hosts: web
  become: true
  tasks:
    - name: Ensure nginx present
      ansible.builtin.package:
        name: nginx
        state: present
    - name: Enable service
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

Idempotence, inventories, secrets via Vault/Ansible Vault — not plaintext.

6. Terraform (IaC)

resource "azurerm_resource_group" "rg" {
  name     = "rg-prep-demo"
  location = "eastus"
}

# plan before apply; remote state; modules; least-privilege SPN

Say: “Plan is the contract. Apply is deliberate. State is sensitive.”

7. Docker

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER nobody
CMD ["gunicorn", "app:app"]

Layers, non-root, healthchecks, image scanning basics.

8. Packer

Golden images: bake agents/tools once, ship immutable AMIs/images, reduce snowflake VMs.

9. Consul & Vault

  • Consul — service discovery / health; know what problem it solves.
  • Vault — dynamic secrets, short TTLs, audit logs; never commit tokens.

10. Jenkins Pipeline as Code

Declarative Jenkinsfile, agents, credentials bindings, artifacts. Tie to Programming track Groovy section.

11. CI/CD + ATDD mindset

Build → test → security scan → deploy → verify. Acceptance tests describe behavior before code. Fail the pipeline on red tests.

12. IaC culture

Everything reviewable: network, IAM, app config. Drift detection. No “clickops” as the source of truth.

13. RCA cycles

Timeline → blast radius → contributing factors → corrective actions → prevention
5 Whys + blameless notes; separate symptom from cause

14. Monitoring, alerting, metrics

USE/RED methods, SLIs/SLOs, alert on symptoms users feel, runbooks linked from alerts. Math track nines apply here.

15. Data stores overview

  • RDBMS — transactions, schema (Postgres/SQL Server).
  • NoSQL — document/key-value at scale.
  • NewSQL / Big Data — when consistency + scale or analytics lakes matter. Know tradeoffs, not every product.

16. Fintech / SaaS context

Change control, segregation of duties, audit trails, data residency, incident comms. Banks care that you respect risk — show it in how you describe pipelines and access.
