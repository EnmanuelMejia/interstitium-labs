Prep · Phase 3 · Track C

DevOps ↔ JD map

Phase 3 of the zero→interview plan. Each module maps to bullets typical of a Sr. Associate DevOps Engineer JD (BNY Mellon–style). Prep only — not employment. Pair with Math, Programming, and BNY interview drills.

Phase 3 lab path GitLinuxNetworkingAzure AnsibleTerraformDocker PackerVault & ConsulJenkins CI/CDRCAMonitoringData storesFintech context

Phase 3 focus (zero-knowledge plan)

  1. Git — branches, PRs; host the Python project on GitHub.
  2. Terraform — Azure VMs + networks (HashiCorp Learn).
  3. Ansible — install Apache (or nginx) on Linux.
  4. Jenkins — Pipeline as Code for the Python app.
  5. Docker — containerize a Flask app.
  6. Vault + Consul — HashiCorp Learn tracks.
  7. Azure — VM, AKS awareness, Blob, VNet, LB + Microsoft Learn Azure Fundamentals.
  8. Linux — Linux Journey (perms, processes, tuning).
  9. Data — PostgreSQL basics + MongoDB University intro.

Capstone trio: (1) Python restart Azure VMs via API · (2) Terraform HA web on Azure · (3) Jenkins test→Docker→Azure.

How to study each module

  1. Read the “say in interview” line aloud.
  2. Do the lab minimum.
  3. Write a 5-bullet RCA or design note in your evidence folder.

1. Git & collaboration

JD: branching, PRs, code review culture.

git switch -c feat/healthcheck
git add . && git commit -m "add healthcheck script"
git push -u origin HEAD
# open PR; request review; squash merge

Say: “I treat infra as code in Git — small PRs, protected main, signed-off reviews.”

Lab: publish Phase 2 Python project with README, LICENSE, and a sample PR.

2. Linux administration

systemctl status nginx
journalctl -u nginx -n 100 --no-pager
ss -tulpn | head
chmod 640 /etc/app/app.env
useradd -r -s /usr/sbin/nologin appuser

Follow Linux Journey: permissions, processes, packages, networking.

3. Networking & firewalls

# allow 443 from internet → load balancer
# allow 8080 only from LB subnet → app subnet
# deny all else
curl -v https://example.com

4. Public cloud (Azure-first)

Subscriptions, RGs, RBAC, VNets, managed identities, tags. Know AWS/GCP name twins.

Lab min: VM + NSG + diagnostics in portal once, then recreate intent in Terraform. Touch Blob, LB, skim AKS concepts.

5. Ansible

- hosts: web
  become: true
  tasks:
    - name: Ensure apache2 present
      ansible.builtin.package: { name: apache2, state: present }
    - name: Enable service
      ansible.builtin.service: { name: apache2, state: started, enabled: true }

Idempotence, inventories, Vault for secrets.

6. Terraform (IaC)

resource "azurerm_resource_group" "rg" {
  name     = "rg-prep-demo"
  location = "eastus"
}
# plan before apply; remote state; modules; least-privilege SPN

Say: “Plan is the contract. Apply is deliberate. State is sensitive.”

Project: HA web — VNet, LB, 2+ VMs or scale set, NSGs, remote state.

7. Docker

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER nobody
CMD ["gunicorn", "app:app"]

Lab: Flask (or FastAPI) app image + healthcheck + scan notes.

8. Packer

Golden images: bake agents/tools once; reduce snowflake VMs.

9. Consul & Vault

  • Consul — service discovery / health.
  • Vault — dynamic secrets, short TTLs, audit; never commit tokens.

Complete HashiCorp Learn intro tutorials; screenshot evidence into portfolio notes.

10. Jenkins Pipeline as Code

Declarative Jenkinsfile for the Python app: Test → Build image → Push → Deploy (Azure). Credentials bindings only.

11. CI/CD + ATDD mindset

Build → test → security scan → deploy → verify. Fail red. Acceptance tests describe behavior.

12. IaC culture

Everything reviewable. Drift detection. No clickops as source of truth.

13. RCA cycles

Timeline → blast radius → contributing factors → corrective actions → prevention

14. Monitoring, alerting, metrics

USE/RED, SLIs/SLOs, runbooks on alerts. Math track nines apply.

15. Data stores overview

  • PostgreSQL — transactions, backups, connection basics.
  • MongoDB — document model intro (University free tier).
  • Know tradeoffs; you are not the DBA of record on day one.

16. Fintech / SaaS context

Change control, segregation of duties, audit trails, data residency, incident comms.
