Student quickstart

Clone → bootstrap → kind-up

Copy-friendly commands. Requires Docker, kind, kubectl, and Make. Optional: fish (some apply scripts), pre-commit, MkDocs.

1 · Clone

git clone https://github.com/EnmanuelMejia/devops-superlab.git
cd devops-superlab

2 · Tooling hooks

make bootstrap

3 · Local cluster

make kind-up

4 · Apply a documented env flow

make kustomize-dev
kubectl -n superlab-dev get deploy,svc,hpa

5 · Optional · GitOps + policy

make argocd-bootstrap
make gatekeeper-bootstrap

6 · Tear down

make kind-down

Full walkthrough lives in the repo’s docs/ (MkDocs). Host-local helpers (e.g. some fish scripts) are optional — documented make targets are the portable path.

Concept glossary

The words this lab uses

  • kind — Kubernetes-in-Docker: the local cluster engine; make kind-up brings up the whole lab on your machine.
  • Kustomize — the manifest layer of the repo: base manifests plus environment overlays applied through the Makefile's kustomize-dev flow.
  • Argo CD — the GitOps control plane: install manifests plus app-of-apps live under gitops/; desired state stays in git, the cluster is synced to it.
  • GitHub Actions (GHA) — the CI layer under .github/workflows/: CI, security, docs, Kustomize validate, Helm OCI release — pipelines you can open in an interview.
  • Gatekeeper / Conftest — the policy layer under policies/: admission constraints and Rego checks that refuse non-compliant workloads before they land.
  • MkDocs — the docs site under docs/: quickstart, GitOps, pipelines, and ops narrative — the interview docs you walk a hiring manager through.
  • App-of-apps — the Argo CD pattern where one Application manages the rest; the lab's way of bootstrapping the whole GitOps control plane from one root.
  • Portfolio lab — the honest label for this repo: inspectable, interview-ready skill evidence that is not a customer production deployment and not paid production tenure.

Worked procedure

Bootstrap to first deploy, in order

  1. Clone. git clone https://github.com/EnmanuelMejia/devops-superlab.git and cd in. Requires Docker, kind, kubectl, and Make on your machine.
  2. Bootstrap tooling. Run make bootstrap — the documented entrypoint for host dependencies (optional fish helpers and pre-commit are documented, not required).
  3. Bring up the cluster. Run make kind-up and confirm nodes are Ready with kubectl get nodes.
  4. Deploy the demo env. Run make kustomize-dev, then verify with kubectl -n superlab-dev get deploy,svc,hpa.
  5. Add GitOps and policy (optional). Run make argocd-bootstrap and make gatekeeper-bootstrap; watch a constrained Pod get denied and read the admission message.
  6. Tear down. Run make kind-down when done — the lab is disposable by design; the repo, not the cluster, is the artifact.

Full walkthrough lives in the repo's docs/ (MkDocs). Documented make targets are the portable path.

Project brief

The interview-demo brief

Deliverable: a cloned, running SuperLab plus a walkthrough you can deliver in an interview — a live stack tour: local kind cluster, Kustomize overlays, Argo CD sync, GitHub Actions pipelines, and a policy gate refusing a bad workload on demand.

Acceptance: a practitioner can clone the repo and reproduce your demo cold; you can narrate what each component does and where it would break. Labeled honestly at every step: portfolio lab, not customer production, not paid production ownership.
