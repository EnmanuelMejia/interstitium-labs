The sequence

The math, taught here — not outsourced.

Every machine learning system is mathematics made executable: data is vectors and matrices, models are parameterized functions, training is optimization, inference is probability. This sequence teaches that spine on this page — original lessons with definitions, worked examples, diagrams, and in-browser exercises you can validate yourself. Linked university materials appear only as further study at the end of each module.

Syllabus

  1. Vectors and Matrices (~45 min) — notation, dot products, norms, the dimension rule. You will be able to check any Wx shape before you compute it.
  2. Eigenvalues, Eigenvectors, and the SVD (~60 min) — characteristic equations, spectral theorem, the master factorization. You will be able to explain PCA as eigen-decomposition.
  3. Calculus: Derivatives, Gradients, the Chain Rule (~50 min) — differentiation rules, gradients, backpropagation's engine. You will be able to derive a gradient by hand and predict vanishing/exploding behavior.
  4. Optimization: Convexity, Constraints, Curvature (~60 min) — convex guarantees, Hessians, Lagrange/KKT. You will be able to classify critical points and diagnose training failures.
  5. Probability: Reasoning Under Uncertainty (~60 min) — axioms, Bayes, expectation, variance. You will be able to update beliefs with Bayes' rule and spot base-rate neglect.
  6. Statistics and Estimation (~60 min) — distributions, MLE, MAP/regularization, overfitting. You will be able to derive an MLE and read a train/test gap.

Prerequisites

  • High-school algebra and comfort with functions; basic programming helps but is not required.
  • Nothing else — Module 1 assumes you are meeting linear algebra for the first time.

How to use it

  • Work the modules in order; each builds on the last.
  • Do every in-browser lab — the validators catch exactly the mistakes beginners make.
  • Copy derivations by hand into a notebook. Watching math is entertainment; doing it is education.
  • Mark each module complete as you finish; your progress persists in this browser.

The curriculum

6 modules, in order.

Module 1 · ~45 min

Vectors and Matrices: the Language of Data

Learning objectives

  • Read vector and matrix notation fluently: dimensions, transpose, dot product, norm
  • Multiply matrices by hand and check dimensions before you compute
  • Explain what the equation Ax = b means geometrically
  • Use the dimension rule to catch shape bugs in model code

Key concepts, explained

Vector. An ordered list of numbers, written x = (x1, x2, …, xn). Geometrically it is an arrow from the origin; in ML it is one data example (n features) or one row of a dataset.
Matrix. A rectangular array of numbers with m rows and n columns — shape m × n. A dataset with m examples and n features is an m×n matrix. A neural-network layer is a matrix multiplication.
The dot product and the norm

The dot product of u = (u1, u2) and v = (v1, v2) is u·v = u1v1 + u2v2. It measures alignment: positive when the arrows point the same way, zero when they are perpendicular, negative when opposed. The (Euclidean) norm ||x|| = √(x12 + … + xn2) is the arrow's length. Cosine similarity — the workhorse of embeddings and retrieval — is just a normalized dot product.

Matrix multiplication, and the dimension rule

Multiplying an m × n matrix W by an n × p matrix V is legal only if the inner dimensions agree (both n), and the result has the outer shape m × p. Entry (WV)ij is the dot product of row i of W with column j of V. The single most common bug in ML code is a shape mismatch — train yourself to check inner dimensions before computing, the way you check units before trusting a physics answer.

Worked example Let 2−10403 times 15−2. Row 1 dot (1, 5, −2) = 2(1) + (−1)(5) + 0(−2) = −3. Row 2 dot (1, 5, −2) = 4(1) + 0(5) + 3(−2) = −2. Result: the 2-vector (−3, −2). Shape check first: (2×3)(3×1) → inner 3 = 3 ✓, outer gives 2×1 ✓.
What Ax = b means

Read it two ways. Row-wise: each equation is a dot product of a row of A with x equaling one entry of b. Column-wise (the useful way): Ax is a linear combination of the columns of A, with the entries of x as weights — and b asks whether that combination can reach a target. Every "fit parameters to data" problem in ML is Ax = b in disguise: the columns are your features, x the weights you seek, b the labels.

Module 2 · ~60 min

Eigenvalues, Eigenvectors, and the SVD

Learning objectives

  • Define eigenvectors/values and compute them for 2×2 matrices by hand
  • Explain why covariance matrices have orthogonal eigenvectors
  • State the SVD and read the shapes of U, Σ, VT
  • Connect PCA and low-rank approximation to eigen-decomposition

Key concepts, explained

Eigenvector / eigenvalue. A nonzero vector v with Av = λv is an eigenvector of A; λ is its eigenvalue. The matrix stretches v by λ without rotating it — these are the matrix's preferred directions.

To find them, rewrite as (A − λI)v = 0: a nonzero v exists exactly when A − λI is singular, i.e. det(A − λI) = 0 — the characteristic equation.

Worked example A = 3102. Then det(A−λI) = (3−λ)(2−λ) − 0 = 0, so λ = 3 or λ = 2. For λ=3: (A−3I)v=0 gives v = (1, 0) (check: A(1,0) = (3,0) = 3(1,0) ✓). For λ=2: v = (−1, 1) (check: A(−1,1) = (−2,2) = 2(−1,1) ✓). Shortcut for 2×2: λ = (tr ± √(tr2 − 4det)) / 2, where tr is the trace (diagonal sum).
Why covariance eigenvectors are orthogonal

A covariance matrix C is symmetric (CT = C). The spectral theorem says every real symmetric matrix has real eigenvalues and orthogonal eigenvectors. That is why PCA works: the principal components — eigenvectors of the covariance — form a proper perpendicular coordinate system aligned with the data's variance, and projecting onto the top few keeps the most information per dimension.

The SVD: the master factorization
Singular value decomposition. Every m × n matrix factors as A = UΣVT: U (m×m) and V (n×n) are orthogonal (rotations/reflections), and Σ (m×n) is diagonal with the singular values σ1 ≥ σ2 ≥ … ≥ 0.

Read it as: rotate (VT), stretch along axes (Σ), rotate again (U). Truncating to the top k singular values gives the best rank-k approximation of A (Eckart–Young) — the engine behind image compression, recommender systems, and latent-factor models. The singular values also diagnose your data: a fast decay means low effective dimensionality; a flat tail means noise.

Module 3 · ~50 min

Calculus: Derivatives, Gradients, and the Chain Rule

Learning objectives

  • Compute derivatives with the power, product, and chain rules
  • Explain what a gradient is and why optimization steps against it
  • Trace backpropagation to the chain rule, and vanishing gradients to products of small factors
  • Read integrals as accumulation — the language probability speaks

Key concepts, explained

Derivative. f′(x) measures how f's output responds to a nudge of its input — the slope of the tangent line, the instantaneous rate of change. In ML the "input" is a parameter and the "output" is the loss: the derivative says which way to push the parameter to lower the loss.

Three rules carry 95% of ML calculus. Power rule: d/dx xn = nxn−1. Product rule: (fg)′ = f′g + fg′. Chain rule: if y depends on u and u on x, then dy/dx = (dy/du)(du/dx) — derivatives multiply along a composition.

Worked example Let L(w) = (w12 + 2w2)2. Set u = w12 + 2w2, so L = u2. By the chain rule, ∂L/∂w1 = 2u · 2w1 = 4w1(w12 + 2w2), and ∂L/∂w2 = 2u · 2 = 4(w12 + 2w2). At (w1, w2) = (1, 1): gradient = (12, 12) — steepest increase points along (1,1), so a descent step moves toward (−1,−1).
The gradient and why descent follows its negative

In many variables, the derivative becomes the gradient ∇L: the vector of partial derivatives, pointing in the direction of steepest increase. Gradient descent iterates w ← w − η∇L(w) — stepping against the gradient, downhill. Every optimizer you will ever meet (momentum, Adam, second-order methods) is a refinement of this one line.

The chain rule is backpropagation

A neural network is a long composition of functions; the loss's gradient with respect to an early weight is a product of every layer's local derivative along the path — the chain rule executed systematically. This immediately explains deep learning's gradient pathologies: vanishing gradients are products of many factors < 1 shrinking to zero; exploding gradients are products of factors > 1 blowing up. You never need to hand-derive backprop (autodiff does it), but the chain rule tells you why depth is dangerous.

Integrals as accumulation

The integral accumulates: area under a curve, total from a rate. Its ML role is probability — an expectation is an integral of values weighted by their density, and "probabilities sum to one" is the integral doing bookkeeping. Hold the intuition (integral = weighted accumulation) into Module 5.

Module 4 · ~60 min

Optimization: Convexity, Constraints, and Curvature

Learning objectives

  • Define convex sets and functions; state what convexity guarantees
  • Use the Hessian's eigenvalues to classify critical points
  • Write the Lagrangian and state the KKT conditions for constrained optima
  • Diagnose training failures in optimization terms (conditioning, geometry, steps)

Key concepts, explained

Convex function. f(θx + (1−θ)y) ≤ θf(x) + (1−θ)f(y) for all θ ∈ [0,1] — the chord between any two points lies above the graph. One valley, no traps.

Convexity buys the strongest guarantee in optimization: every local minimum of a convex function is a global minimum. Least squares, logistic regression, and SVMs are convex — which is why they are reliable. Deep networks are not, which is why training them is an art informed by this theory.

Curvature: the Hessian classifies critical points

Where the gradient is the slope, the Hessian H — the matrix of second partials — is the curvature. At a point with zero gradient: all eigenvalues of H positive → local minimum; all negative → local maximum; mixed signs → saddle (down in some directions, up in others). A twice-differentiable function is convex exactly when its Hessian is positive semidefinite everywhere. Saddle points — not poor minima — are the typical obstacle in high-dimensional non-convex training.

Worked example f(x,y) = x2 − y2. Gradient (2x, −2y) = (0,0) at the origin. Hessian H = 200−2, eigenvalues 2 and −2 — mixed signs, so the origin is a saddle: a minimum along y = 0, a maximum along x = 0. Gradient descent slows to a crawl near saddles because the gradient itself is tiny there.
Constraints: Lagrange and KKT

To minimize f(x) subject to g(x) = 0, form the Lagrangian L = f + λg: at the optimum, ∇f is parallel to ∇g — you cannot improve f without violating the constraint. The Karush–Kuhn–Tucker (KKT) conditions generalize this to inequality constraints: stationarity, primal/dual feasibility, and complementary slackness (λi gi = 0 — either the constraint binds or its multiplier is zero). SVMs are KKT conditions wearing a trench coat: the support vectors are exactly the training points whose constraints bind.

The engineer's diagnostic taxonomy

When training misbehaves, classify it: bad conditioning (Hessian eigenvalues span orders of magnitude → slow, zigzagging descent — precondition or adapt the step); bad geometry (saddles, flat regions — momentum, restarts); bad constraints (infeasible projections — check the feasible set); bad step (learning rate — Lab 3). Theory gives the taxonomy; the taxonomy gives the fix.

Module 5 · ~60 min

Probability: Reasoning Under Uncertainty

Learning objectives

  • State the probability axioms and compute with complements and independence
  • Apply Bayes' rule and explain base-rate neglect
  • Define expectation and variance; compute both for simple distributions
  • Read a classifier's output as a probability, not a verdict

Key concepts, explained

Probability axioms. Probabilities are numbers in [0, 1]; the whole sample space has probability 1; disjoint events add. Everything else — including all of ML's uncertainty machinery — follows.

Two workhorse rules: the complement P(not A) = 1 − P(A), and independence: A, B independent means P(A and B) = P(A)P(B). Independence is a strong claim — assuming it when features are correlated is a classic modeling error (naive Bayes names its sin honestly).

Conditional probability and Bayes' rule
Bayes' rule. P(H|E) = P(E|H) P(H) / P(E). The posterior (belief after evidence) is proportional to the likelihood (how well the hypothesis predicts the evidence) times the prior (belief before evidence).
Worked example — the base-rate trap A test detects a condition 90% of the time (P(+|disease) = 0.9) with a 5% false-positive rate (P(+|healthy) = 0.05). The condition affects 1% of people (P(disease) = 0.01). You test positive — how worried? P(disease|+) = 0.9 × 0.01 / (0.9 × 0.01 + 0.05 × 0.99) = 0.009 / 0.0585 ≈ 15.4%. Despite a "90% accurate" test, a positive means only a 1-in-6 chance — because the condition is rare, false positives from the healthy 99% swamp the true positives. Forgetting the prior is base-rate neglect, and it is why every alerting system and classifier threshold must be read with Bayes, not with gut.
Expectation and variance

The expectation E[X] is the probability-weighted average — the integral from Module 3 made concrete: E[X] = ∑ x · P(X=x). The variance Var(X) = E[(X−μ)2] measures spread. A fair die: E = (1+2+3+4+5+6)/6 = 3.5. Every "expected loss" you minimize in training is one of these.

Classifiers output probabilities

A classifier's 0.83 is not a verdict — it is P(positive | features) under the model's assumptions, calibrated (or not) by training. Thresholds convert probabilities to decisions, and the threshold encodes costs: in fraud or medicine, missing a positive costs far more than a false alarm, so the threshold drops. Bayes plus costs is the whole decision theory of applied ML.

Module 6 · ~60 min

Statistics and Estimation: From Data to Models

Learning objectives

  • Name the Bernoulli, Binomial, and Gaussian distributions and their parameters
  • Derive the maximum-likelihood estimate for a coin's bias by hand
  • Explain MAP estimation and its equivalence to regularized fitting
  • Diagnose overfitting as a train/test gap, and name the standard defenses

Key concepts, explained

A random variable is an uncertain quantity with a distribution. Three distributions run ML: Bernoulli(p) — one coin flip, 1 with probability p; Binomial(n, p) — heads in n flips, mean np; Gaussian(μ, σ2) — the bell curve, mean μ, variance σ2, with the 68–95–99.7 rule (that fraction of mass within 1, 2, 3 standard deviations).

Maximum likelihood: the fitting principle
Maximum likelihood estimation (MLE). Choose the parameters that make the observed data most probable under the model. Take the log (monotone, harmless), negate it, and you have a loss — the negative log-likelihood that gradient descent minimizes.
Worked example — the smallest MLE Coin flips: h heads, t tails, bias p unknown. Likelihood L(p) = ph(1−p)t; log-likelihood l(p) = h log p + t log(1−p). Set the derivative to zero: h/p − t/(1−p) = 0 ⇒ p̂ = h / (h + t) — the observed frequency. Seven heads in ten flips → p̂ = 0.7. Logistic regression, language models, diffusion models: all maximum likelihood in heavier clothes.
MAP: priors are regularization

Maximum a posteriori estimation maximizes P(params | data) ∝ P(data | params) P(params) — likelihood times prior. A Gaussian prior on weights (P(w) ∝ exp(−||w||2/2σ2)) has log-prior −||w||2/2σ2 — exactly the ridge (L2) penalty from Module 2. Regularization is a prior belief that weights should be small, written in the language of probability. (A Laplace prior gives the lasso's L1 penalty.)

Overfitting: the train/test gap

A model that memorizes training noise scores brilliantly on train and poorly on held-out test data — overfitting. The defenses form a ladder: more data, simpler models, regularization (Module 4's penalties = Module 6's priors), early stopping, and honest validation (never tune on the test set — a tuned-on test set is a validation set wearing a fake mustache). The train/test gap is the single number that tells you whether learning happened or memorization did.
