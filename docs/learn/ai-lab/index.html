The track

Ship the system, not just the weights.

Most AI discourse is model discourse — parameter counts, benchmark tables, release notes. The engineering that matters lives one layer out: how a model runs on hardware you control, what surrounds it to make it useful, and how you keep it honest while it works. A language model by itself is a text-completion engine. Everything that turns it into a product — retrieval, memory, tool use, sandboxing, evaluation, monitoring — is infrastructure you build, operate, and pay for. This track teaches that infrastructure.

It opens where dependence ends: running open-weight models locally. Quantization and the GGUF format, inference runtimes like llama.cpp and Ollama, desktop apps like LM Studio and Jan, web interfaces like Open WebUI — and the honest separation of production serving stacks like vLLM, which are a different discipline for a different audience. The second pillar is the agent stack: the frameworks that structure agent behavior, the memory systems that let agents persist knowledge across sessions, the sandboxed runtimes that make executing generated code survivable, and the eval and observability layers that tell you whether the system works or merely looks like it works. The third pillar is a configuration pattern for agentic coding itself: one model writes, a silent advisor reviews at three trigger points, specialist subagents divide the labor, and a cheap router keeps the expensive model focused on genuinely hard decisions.

Every module below explains its concepts in prose — no empty outlines — and every lab runs against verified open-source projects and free documentation. Finish the track and you can size a local inference setup to your hardware, architect the loop from request to deploy with the right layer at each step, and configure an agentic coding setup that catches its own mistakes.

The machinery

The ideas, stated plainly.

The model is one folder

A trained model is a file — weights, a tokenizer, a config. Everything else in an AI product is scaffolding you own: the prompt pipeline, the tools the model can call, the memory it reads and writes, the sandbox its code runs in, the tests that judge its behavior, the traces you inspect when it fails. When someone says "we built an AI product," ask what the folders around the model folder contain. That is where the engineering is, and where the failure modes live.

Local inference is an economics decision

Running a model on your own hardware trades API bills and data egress for capital cost and operational burden. Quantization — storing weights at reduced precision — is what makes this trade survivable: a model that needs a datacenter at full precision fits on a workstation at 4-bit. The skill is knowing the exchange rate: what you lose in fidelity at each quantization level, what your VRAM and memory bandwidth actually bound, and when the right answer is "this workload belongs on an API." Local is a choice with a price, not a virtue with a halo.

The agent loop: request to deploy

Every agent system, however marketed, reduces to one loop: a request arrives, an agent reasons and acts, memory persists what matters, tools extend what the model can do, a runtime executes the side effects, evals judge the outcome, failures retry, and working behavior deploys. Each stage is a separate engineering discipline with its own failure modes — memory goes stale, tools get abused, sandboxes leak, evals lie to you. The track's discipline is to treat each stage as load-bearing and instrumented, never as magic.

Generation must be separated from verification

A model that writes and a model that checks should not be the same process wearing two hats. The writer is optimized for momentum — propose, build, move on. The verifier is optimized for suspicion — is this the right plan, is this error a dead end, what did speed skip? Running both in one undifferentiated session produces confident output with unchecked assumptions. The pattern this track teaches makes the separation structural: distinct roles, distinct trigger points, and the cheap decisions routed away from the expensive mind.

The curriculum

Three pillars, from your hardware to your review loop.

Pillar 1

Run it yourself — the Local AI Lab

Why local inference exists (privacy, latency, cost, control), and what it actually costs you. Quantization and the GGUF ecosystem: what reduced precision buys and what it sacrifices. The runtime layer — llama.cpp, Ollama, LocalAI — then the desktop layer (LM Studio, Jan, GPT4All), the web-UI layer (Open WebUI, text-generation-webui, koboldcpp), and the production serving tier honestly separated: vLLM is a serving stack for operators, not a desktop tool. Hardware sizing in qualitative tiers — what constrains you is memory bandwidth and capacity, and the page teaches you to read those constraints instead of memorizing numbers. The lab track walks install to model pull to local serving to chat UI to API calls. Companion: The Local AI Lab study sequence.

Pillar 2

Build around it — Agent Stack Operations

The full pipeline as one operations loop: request to agent to memory to tools to runtime to eval to retry to deploy. Agent frameworks (typed agents, structured outputs, graph-based long-running workflows, code-executing agents), memory systems (persistent vector memory vs. temporal knowledge graphs — and why they are different answers to different questions), sandboxed execution for AI-generated code, evals that test LLM behavior the way unit tests test code, and production observability (tracing, monitoring). Honest engineering throughout: prompt-injection surfaces, eval flakiness, the cost and latency of agentic loops, and what to do when a dependency goes quiet — the page keeps a flagged repo as a dependency-risk lesson rather than silently dropping it. Companion: Agent Stack Operations study sequence.

Pillar 3

Check the work — the Main-Writer / Silent-Advisor Pattern

A community-reported configuration for agentic coding, taught as a transferable pattern rather than a product feature. One model owns the session and writes every line; a silent advisor reads the whole session and speaks only at three trigger points — a plan is proposed, the same error returns twice, a task is marked done. Beneath them, specialist subagents (explorer, worker, researcher) divide reading, editing, and documentation; a cheap triage router answers the trivial fork decisions so the expensive model only sees genuinely hard splits. The page wires the pattern honestly against the official docs — what the tooling actually supports, what practitioners construct by hand — and names the failure modes: over-review, advisor latency, false positives, and when the whole apparatus is overkill. Companion: The Main-Writer / Silent-Advisor Pattern study sequence.

Corrections

The legends, graded.

"A bigger model solves the product." Backwards. Past a certain capability floor, product quality is dominated by the system around the model — retrieval quality, tool design, eval coverage, the review loop. Teams that upgrade the model while neglecting the scaffolding get a smarter engine in the same broken car.

"Open weights means open source." Distinct things. Open weights give you the artifact; the license governs what you may do with it, and licenses in this space range from permissive to research-only to commercial-use-restricted. Read the model card and the license text — the download page is not the permission slip.

"Local means private." Only if the rest of the pipeline is. A local model queried through a telemetry-phoning UI, or fine-tuned on data that syncs to a vendor cloud, is not a private system. Privacy is a property of the whole data path, not of where the weights sit.

"Evals prove the agent works." Evals prove the agent passed the evals. LLM-as-judge setups inherit the judge's biases, small eval suites miss the long tail, and a green dashboard with a bad metric is worse than no dashboard — it manufactures confidence. The honest question is always: what would this eval miss?

"Agents replace engineers." Agents replace keystrokes, not judgment. Somebody still defines the objective, scopes the blast radius, reviews the diff, and owns the incident. The main-writer / silent-advisor pattern exists precisely because the failure mode of unsupervised agents is confident, fast, wrong.
