Narrator: Narrator: In system design interviews, start with the naive path — every request hitting the database — then identify the bottleneck: repeated reads of hot data.

Narrator: Narrator: Add a cache tier — hits return in microseconds, misses fall through to the database and populate the cache. Hit ratio is the metric that matters.

Narrator: Narrator: Then handle writes — cache-aside lazily loads, write-through keeps both in sync. And the hard part: invalidation strategy when underlying data changes.
