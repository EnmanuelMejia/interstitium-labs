Concept glossary

The words this directory uses

  • Learning path — an ordered, phased curriculum with outcomes, Adapt gates, SuperLab proof, and a capstone; every card on this directory answers "what will I be able to DO?"
  • Adapt gate — a placement checkpoint at /adapt/ that targets only your ready-to-learn fringe, so phases skip what you already know.
  • Noah side-quest — a Socratic prompt attached to each phase that asks you to connect theory to a deployable artifact.
  • Prove it — the hands-on artifact each phase demands: weekly GitHub commits, SuperLab runs, a capstone README — evidence, not attendance.
  • Exceed — a path that runs past the shape of the standard curriculum: same domains, deeper bar, inspectable proof.
  • Vendor map — the reference that points official certification depth at third-party providers; we orchestrate, we do not clone their content.
  • Evidence portfolio — your local log of artifacts (SuperLab verifies, capstone READMEs, interview packets), stored on your device in il.paths.v1.
  • Default sequencer — the recommended order below: foundations first, DevOps Zero→Hire plus weekend SuperLab, then depth electives.

Worked procedure

Run the directory, start to finish

  1. Place your fringe. Start with Adaptive Foundations or Ops Math and run the Adapt gate — it targets only what is ready to learn.
  2. Pick one path. Choose the card whose outcome matches the screen or role you want; press Start path. Progress stays in il.paths.v1 on your device — no account needed.
  3. Work phases in order. Each phase lists skills, a prove-it artifact, an Adapt gate, and a Noah side-quest. Check Done only when the artifact exists.
  4. Prove it weekly. Commit to GitHub, run the weekend SuperLab, and log the artifact in the page's evidence log.
  5. Ship the capstone. End with the capstone README and interview packet, then deepen official certification depth via the vendor map.

Project brief

The portfolio brief every path converges on

Deliverable: a public proof portfolio — weekly GitHub artifacts from each phase, a working SuperLab deployment you can screen-share, a capstone README that explains the architecture, and an interview packet (STAR stories scoped to what you built).

Acceptance: a practitioner can clone your artifacts and reproduce them; you can narrate the tradeoffs without slides. Label everything honestly — portfolio is portfolio, not paid production tenure.
