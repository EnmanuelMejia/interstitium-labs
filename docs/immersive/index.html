Hands on the keyboard · scene reacts

In-scene CLI lab.

On nine drills — control plane, scheduling, HPA, etcd quorum, NetworkPolicy, RBAC, storage / reclaim, Ingress and AWS Multi-AZ — open CLI lab and type real syntax — sudo mv /etc/kubernetes/manifests/kube-scheduler.yaml /tmp/, kubectl auth can-i list pods -n dev --as alice, kubectl apply -f api-allow-frontend.yaml, kubectl patch pv pv-1 -p …Retain, curl -sI https://shop.example.com/api — and the authored 3D scene re-tints. (The Ingress drill covers the Ingress API; ingress-nginx itself was retired by the Kubernetes project on 2026-03-24 and Gateway API is the successor.) Each drill has tasks with ordered steps that are checked as you go. Press Check (or type check) and Lab Muse tells you why a step is not verified yet — out of order, right command in the wrong cluster state, or the live state is not true — lights up where to look in the 3D scene, offers a tip on the second miss, and prints the exact command only if you ask for solution. Turn on Lab Muse voice to hear it (your browser’s own speech synthesis). Any step where you needed solution, or failed check twice, becomes a spaced-repetition card on this device: the review re-opens that drill with the earlier steps replayed and asks you to type the step again. Where your browser supports speech recognition, Speak lets you say “check”, “hint” or a command; spoken commands land in the prompt for you to confirm with Enter (the browser vendor may process the audio; Interstitium never receives it). The coach is deterministic rules over the sim, not an AI model. Simulated shell: commands are parsed in this browser and drive the same rules engine; output is computed, not from a real cluster or AWS account. No hosted lab fleet.

CKA CNI / pod networking (3D exceed)

Competitors mostly show flat CNI diagrams. Authored cni-pod-network.glb — nodes, pods, veth, CNI bridge, overlay arcs, ClusterIP, CoreDNS. Blender CLI polished 2026-10-01. Not a hosted networking fleet. Interactive (2026-10-08): remove the CNI plugin, overlap the pod CIDR with the VPC, drop kube-proxy or CoreDNS — nodes go NotReady, veth pairs vanish, overlay arcs and the Service VIP turn red exactly where the packet path breaks. CLI lab (2026-10-27): three typed tasks. Install Calico on a cluster whose nodes are NotReady. Move pods off an IP pool that overlaps the VPC, in the order Calico documents: new pool, disable the old one, recreate the pods. Bring back a missing kube-proxy with kubeadm init phase addon kube-proxy. You probe with ping, curl and nslookup from a client pod. The shell is simulated and runs on a rules engine: the manifests are trimmed stand-ins, and there is no live cluster and no real Calico.

CKA RBAC authz graph (3D exceed)

Interactive (2026-10-07): delete bindings, flip RoleBinding ↔ ClusterRoleBinding, switch namespace — the granted edges light up exactly as kubectl auth can-i would answer.

Service mesh sidecar (optional exceed)

service-mesh-sidecar.glb — control-plane vs sidecar data-plane, mTLS hops, xDS config arcs. Blender CLI polished 2026-10-01. Interactive (2026-10-08): label the namespace without restarting, flip PeerAuthentication STRICT ↔ PERMISSIVE, kill istiod — the client sidecar only appears for recreated pods and plaintext hops turn red under STRICT (Istio semantics; not CKA core). CLI lab (2026-10-27): three typed tasks. Fix a Connection reset by peer under STRICT by labelling the namespace and recreating the pods. Migrate PERMISSIVE to STRICT in a safe order, with the X-Forwarded-Client-Cert header as proof that a hop is mTLS. Then watch istiod at zero block new pods through the injection webhook while existing traffic keeps flowing, and check istioctl proxy-status. The shell is simulated: there is no live mesh and no real Envoy or istiod.

CKA Gateway API (3D exceed, 2026-10-21)

Same authored ingress-gateway.glb, read as Gateway API: the proxy is the Gateway’s data plane, the TLS node is the HTTPS listener, the rules are an HTTPRoute with a cross-namespace backendRef. Interactive: take the GatewayClass controller away (Pending, no ADDRESS), point the route at a hostname no listener serves (NoMatchingListenerHostname → 404), drop the ReferenceGrant (RefNotPermitted → 500), delete the listener’s certificate Secret (InvalidCertificateRef → TLS handshake fails), flip PathPrefix ↔ Exact. Open the CLI lab for four typed tasks over gatewayclass / gateway / httproute / referencegrant. Rules engine and simulated shell — GatewayClass lab-gw is a lab implementation, not a live Gateway or a vendor controller. No new asset.

CKA control-plane failure drill (interactive 3D)

The lecture scene lecture-k8s-control-plane.glb (kube-apiserver, kube-scheduler, kube-controller-manager, five workers with kubelet LEDs; Blender CLI polished 2026-10-01) becomes a troubleshooting drill. Interactive (2026-10-08): take down the API server, the scheduler, the controller-manager or one kubelet, predict what still works, then watch the component go dark — running pods survive an API outage; Pending, unreplaced or NotReady are each a different culprit.

CKA worker-node troubleshooting (new 3D asset, 2026-10-22)

Troubleshooting is 30% of the CKA. A new authored scene, node-troubleshoot.glb, opens up node-01: systemd supervising the kubelet, the kubeadm drop-in, the CRI socket into containerd, the CNI config, the node Lease to the API server, pods ranked by QoS for eviction, a nodefs gauge and the journal. Built with the glTF kit and polished with the Blender CLI, not hand-sculpted. Interactive: predict, then watch the node react. A bad ExecStart exits 203/EXEC, and the fix does not take until systemd reloads the unit. If containerd stops, running containers survive but the node goes NotReady. An empty /etc/cni/net.d gives “cni plugin not initialized”. When nodefs drops below 10%, the kubelet evicts BestEffort pods first. The CLI lab has four typed tasks with real ssh node-01 sessions, systemctl, journalctl, crictl and sed -i. The shell is simulated and runs on a rules engine: there is no VM and no live node, and timers such as the 300s eviction toleration are explained, not counted down.

CKA Service & DNS troubleshooting (new 3D asset, 2026-10-23)

The other half of CKA Troubleshooting. A new authored scene, service-dns.glb, lays out three namespaces: a client pod and its /etc/resolv.conf, Service api with its port, selector and EndpointSlice, the api pods and their container ports, kube-proxy, the kube-dns Service with the CoreDNS pods and their Corefile, a namespace egress policy, and Service db in another namespace. Built with the glTF kit and polished with the Blender CLI, not hand-sculpted. Interactive: predict, then watch the path light up where it breaks. A selector that matches nothing leaves the EndpointSlice empty and the connection refused. A targetPort that is not the container port gets refused too, even though the endpoints look fine. A Corefile typo crash-loops CoreDNS, so every lookup fails while ClusterIPs still work by IP. A default-deny egress policy without a port 53 rule makes lookups time out. A short name across namespaces returns NXDOMAIN. The CLI lab has four typed tasks with kubectl get endpointslices, nslookup and dig from a debug pod, CoreDNS logs, and a ConfigMap fix with get -o yaml > file, sed -i and apply -f. The shell is simulated and runs on a rules engine: there is no live cluster and no real CoreDNS, and back-off and resolver timeouts are explained, not counted down.

AWS SAA: Multi-AZ failure drill (interactive 3D)

AWS Cloud Quest puts a 3D city around flat solution diagrams; KodeKloud's design challenge is drag-and-drop 2D. Here the architecture itself is spatial and reacts to failure: authored aws-vpc-multi-az.glb — VPC across two AZs, IGW, ALB nodes, zonal NAT, Auto Scaling group, RDS primary + synchronous standby. Fail an AZ, predict first, then watch the ALB drain, the ASG relaunch capacity, and RDS fail over (or not, with Single-AZ). Blender CLI polished 2026-10-06. Rules engine in-browser — no AWS account, no hosted fleet.

AWS IAM policy evaluation walk (interactive 3D)

Authored aws-iam-policy-eval.glb — a request walks six gates (explicit Deny → SCP/RCP → resource policy → identity policy → permissions boundary → session policy) to ALLOW, implicit deny, or explicit deny. Flip statements on and off; the gate that decides lights up. Follows the single-account flow in AWS's “Policy evaluation logic” docs (simplified: cross-account and role-session edge cases noted in the explanations). Blender CLI polished 2026-10-06.
