# Noah jobs workspace

Implemented 2026-10-02 on `codex/project-noah`. Entry point: `/jobs/`. This is an original Interstitium Labs interface adapting job-search workflows to Noah. It is connected to the homepage, Noah workspace, knowledge catalog and sitemap.

## Working behavior

- Public openings load from `/assets/noah-jobs-feed.json` on an explicit click. The first snapshot contains 16 actual Remotive listings, retrieved **2026-10-02T06:40:09.105Z**. No fabricated roles are used. A new workspace shows all role families so the visitor can explore the feed immediately; saved explicit role filters remain intact. The editable target goal defaults to Junior cloud / DevOps. The current snapshot contains no cloud-title matches; that filter’s honest empty state recommends changing filters or bringing a current posting.
- Filters combine title/company/keyword, role family, location text, title-based seniority, work type, source, saved jobs and the visitor’s recorded tracking stage. Filters can be saved locally. Seniority inference uses title words only and does not establish job eligibility.
- Visitors can paste a posting title, company, public HTTPS URL and requirements. Imports never fetch that URL or connect to an account. Canonical URL deduplication removes common tracking parameters and fragments while retaining the posting identity. Imports and tracked postings survive feed reloads. A retained listing absent from the latest loaded snapshot is visibly marked for source verification.
- Saved jobs and **Preparing / Applied / Interview / Closed** stages are device records entered by the visitor. Recording “Applied” does not submit an application.
- The limited skill checklist separates stated skills from learning or missing evidence. Years of paid work, education, authorization and candidate location remain unresolved. Certifications are unchecked by default; no private user profile was baked into the public site. A portfolio remains learning evidence. No hiring percentage or unsupported experience claim is generated.
- Local preparation works without an AI service. Noah review opens a dialog with the bounded prompt and fresh consent. The exact reviewed prompt includes selected postings and supplied evidence. `.converse(prompt, { forceRemote: true, shareMemoryWithRemote: false, sharePageContext: false })` excludes other saved conversation, notes/goals and page context. It saves the review in the device’s shared Noah conversation. Engine provenance and fallback notices come from Noah’s actual response. There is no automatic application, messaging or employer contact.
- Export downloads this workspace’s jobs, evidence, filters and stages. Forget clears its own local-storage key. Noah conversation is managed separately in `/noah/`. Storage failure is disclosed and leaves the current tab usable. Concurrent forget or cross-tab changes invalidate late feed results and job-review display.

## Source boundaries

The [Jobright recommendations page](https://jobright.ai/jobs/recommend) remains an external bridge. No Jobright source code, branding, signed-in recommendations, account profile or credentials were copied. A visitor can manually bring a selected public posting for private review. [Jobright’s official terms](https://jobright.ai/legal/service), dated July 29, 2026, describe restrictions on copying and automated access; no scraping connector is installed.

[Remotive’s official API documentation](https://github.com/remotive-com/remote-jobs-api) was verified on 2026-10-02. Each listing identifies Remotive and links back to its supplied Remotive URL. The interface requires no signup or email address. Provider data is delayed 24 hours. Listings are not submitted to other job aggregators or exposed as Google Jobs structured data. The documentation advises at most four API requests daily.

`node scripts/refresh-noah-jobs.mjs` creates a shared static snapshot. It preserves the existing file on API/validation failure and writes successful data atomically. A six-hour guard covers the previous snapshot and locally recorded request attempts, including failed requests. Visitors only read the shared same-origin file; their page views do not multiply provider API calls. The snapshot is **manually refreshed** by this script; no unrequested scheduled job was created. Coordinate refreshes from one checkout to keep the provider’s aggregate request budget.

## Validation and practical limits

`node --test scripts/tests/noah-jobs.test.js`: **12 passed**, covering URL boundaries, HTML/credential handling, identity/deduplication, compound filters and manual stages, honest evidence matching, corrupt/blocked storage, consent prompt bounds, remote consent and context exclusion, local preparation and the actual attributed snapshot. `node --check` passed for the browser module and refresh script. A second refresh invocation reused the existing snapshot without another provider request.

Browser flows, accessibility and viewport results are recorded by the shared `scripts/test-noah-browser.mjs` suite after integration. Local tests use a disposable browser and mocked remote responses; they are distinct from production deployment and real AI availability. The root audit independently received a successful generic career response from the existing university `/api/noah` endpoint with production-origin CORS; it transmitted no candidate profile or private account data.

The feed is a limited remote-jobs snapshot and may be stale or lack a desired role. Imports and term checks are not résumé parsing or a full recommendation model. No Jobright API authorization, cloud account sync, application automation or employer integration is claimed. The local preview may use Noah’s truthful fallback when its AI endpoint is unavailable. Common credential patterns are redacted; this is not a promise that arbitrary sensitive content is detected. Visitors should review the consent preview and the source posting.
