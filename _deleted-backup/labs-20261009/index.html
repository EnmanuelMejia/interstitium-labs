Concept glossary

The words the labs use

  • SuperLab — the flagship open portfolio lab: kind · Kustomize · Argo CD · GitHub Actions · Gatekeeper. Cloneable proof you can screen-share — not paid production tenure.
  • Scenario card — a guided checklist (exact commands included) for one failure mode or workflow: GitOps sync, Gatekeeper deny, GHA build failure, kind cold start.
  • Playground vs guided — the guided scenario cards run on your machine or in SuperLab; the playground is the deep SuperLab itself. We do not claim a hosted multi-cloud sandbox fleet.
  • Noah Live Assist — in-lab, Socratic coaching: paste errors, get nudges, optional local Ollama router. No fake API keys.
  • Challenge of the Day — the daily proof ritual: one SuperLab check, every day, logged locally.
  • kind — Kubernetes-in-Docker: the local cluster engine behind the SuperLab quickstart (make kind-up).
  • GitOps — the deploy model: desired state lives in git (Kustomize overlays, app-of-apps) and Argo CD syncs the cluster to it.
  • Policy gate — admission control (Gatekeeper constraints, Conftest checks) that refuses bad workloads before they land — the lab's honesty layer.

Worked procedure

Work one lab scenario, start to finish

  1. Pick a scenario card. Choose the failure mode you want to rehearse: broken GitOps sync, Gatekeeper deny, red GHA build, or a cold kind start.
  2. Read the checklist, then run it. Work the card's exact commands on your machine or inside the SuperLab — the cards assume the SuperLab quickstart (make bootstrap → make kind-up).
  3. Get stuck on purpose. When a step fails, paste the error into Noah Live Assist above and take the Socratic nudge — the debugging is the lesson, not the happy path.
  4. Verify the fix. Re-run the card's verification command (kubectl get, argocd app get, or the CI re-run) until the scenario is green.
  5. Log the proof. Note the scenario, the failure, and the fix in your evidence log — that entry is what you narrate in an interview, with the SuperLab screen-shared behind it.

Project brief

The lab portfolio brief

Deliverable: a cloned, running SuperLab plus a lab journal — every scenario card worked with its failure and fix, one interview-ready walkthrough (clone → bootstrap → kind-up → GitOps → policy), and the Challenge-of-the-Day streak to prove cadence.

Acceptance: you can bring the cluster up cold, break a scenario on demand, fix it live, and explain what each gate refused and why. Honest labels throughout: lab = lab, never production tenure.

Scenario · GitOps

Sync a broken Application

Argo CD shows OutOfSync. Trace desired vs live, then sync with respect for hooks.

  • Open Argo UI / CLI; note sync status
  • Diff manifests; identify drift source
  • Sync with prune only if intentional
kubectl get applications -n argocd
argocd app get <name> --grpc-web
argocd app sync <name> --grpc-web

Scenario · Policy

Gatekeeper denies a Pod

A deploy fails admission. Read the constraint message; fix the workload or the template.

  • kubectl describe / events for admission errors
  • Map message → ConstraintTemplate
  • Patch Pod security context; re-apply

kubectl get k8spspprivilegedcontainer
kubectl apply -f apps/demo/ — watch deny
